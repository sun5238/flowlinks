# FlowLinks

FlowLinks 是一款面向源码阅读的 VS Code 扩展。它把散落在源码中的书签组织成可折叠的调用树，并用消息引用连接不同线程或处理流程，便于记录、回顾和继续追踪一条链路。调用和消息关系由你手动建立，扩展不会自行推断调用图。

## 特性

- **按 Group 整理**：一个 Group 对应一条阅读链路，是没有源码位置的树根。可在同一工作区创建多个 Group、重命名并切换活动 Group。相同源码位置可分别加入不同 Group。
- **书签定位**：在源码位置或选区添加节点，编辑器行号栏显示标记；单击树中的节点即可返回源码。普通文本编辑时，标记会跟随位置变化。
- **调用关系**：拖动节点到另一个节点或 Group 来调整调用层级；上移、下移按钮只交换相邻同级节点的位置，整棵子树随节点移动。拖动后会展开新父节点，避免节点看起来消失。
- **消息引用**：从发送节点选择已有接收节点，添加可选的消息名称；单击引用可定位到接收节点。消息行的删除按钮只删除该条链接，不删除发送或接收节点。支持跨 Group 的消息连接。
- **名称与笔记**：添加节点时使用 Tree-sitter 从 C/Rust 源码提取名称，必要时尝试语言服务，再以当前位置源码兜底。节点名称可以手动修改；独立的多行 note 会随节点移动，节点行显示简短预览，悬停可查看完整 note 和文件位置。
- **树视图操作**：节点行提供上移、下移、编辑 note、添加消息和删除图标，右键菜单也保留这些操作。支持全部展开与全部折叠。

## 安装

在 VS Code 的**扩展**视图中搜索 **FlowLinks**，确认发布者为 **FlowLinks**，然后点击**安装**。要求 VS Code 1.90.0 或更新版本。

## 使用流程

1. 在活动栏打开 **FlowLinks**，点击 **Create Group** 并命名。没有 Group 时执行 **Add Node**，扩展也会提示先创建。
2. 打开工作区内的源码文件，将光标放在目标位置，使用编辑器右键菜单中的 **Add Node**，或在命令面板运行 **FlowLinks: Add Node**。新节点默认加入当前活动 Group。
3. 有多个 Group 时，用视图标题栏的 **Switch Active Group** 切换默认目标；也可以右键指定 Group，直接向它添加节点。最近选定或创建的 Group 会在此工作区保留为活动 Group。
4. 拖动节点调整调用父子关系，用树行的上移、下移按钮交换同级顺序；用 **Add Message** 把发送节点连接到已有接收节点。单击源码节点跳转到书签位置，单击消息引用则在树中定位接收节点；悬停在消息行上点击垃圾桶图标可以只删除这条消息链接。
5. 右键 Group 可重命名或删除。删除 Group 前会确认，确认后将删除该 Group 的全部书签、note 及相关消息引用；删除单个节点则保留其子节点，并把它们提升到原位置。

note 输入框中用 `\n` 表示换行，用 `\\` 输入字面上的反斜杠。Group 内同一位置再次执行 **Add Node** 时会定位已有节点，不会重复添加。

## 数据与隐私

单文件夹本地工作区的数据保存在工作区目录的 `.vscode/flowlinks.json`，不同 VS Code 环境打开同一个目录可以共享 Group、书签、note 和关系。工作区内的源码路径以相对路径保存，因此目录在不同环境下挂载到不同位置也能定位；另一个窗口保存后，本窗口会刷新视图。首次打开时，原有的 VS Code `workspaceState` 数据会迁入共享文件。如果另一个环境已有独立旧数据，FlowLinks 会把它备份为 `.vscode/flowlinks.legacy-*.json` 并提示人工核对，不会自动合并。多根工作区和非 `file` 工作区仍使用原来的 `workspaceState`，不跨环境共享。

共享文件在项目目录内，可能被 Git 跟踪；如果不希望提交其中的路径或 note，请将 `.vscode/flowlinks*.json` 加入项目的 `.gitignore`。写入使用临时文件和重命名，避免留下只写了一半的 JSON。如果两个窗口几乎同时修改，最后完成的写入会覆盖另一窗口的整份图，不会自动合并或生成并发冲突备份。删除源码行不会自动删除节点；需要删除书签时使用 **Delete Node**。**Clear Workspace Data** 会清空共享文件中的数据，而不会删除源码或旧环境备份。卸载扩展不会自动清除数据。

此前以 `local-flowlinks.flowlinks` 身份安装的本地测试包与 `FlowLinks.flowlinks` 是两个不同的扩展，工作区数据不会自动迁移；旧包和它的数据也不会被新包自动删除。
